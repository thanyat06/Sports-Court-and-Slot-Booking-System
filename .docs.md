## 2. Model Classes Completed

**Commit ID:** `3272406`  
**Commit Message:** `Models completed`

### Description
This commit records the completion of the model classes used to represent the main entities in the Sports Court & Slot Booking System.

### Models
- **Court:** Represents a sports court and its details, such as court name, sport type, location, hourly rate, and active status.
- **Slot:** Represents a court's scheduled time slot, including its date, start time, end time, availability status, and associated booking.
- **Booking:** Represents a customer's booking, including customer details, court, booking date, time range, duration, amount, and booking status.
- **Payment:** Represents the payment associated with a booking, including amount, payment method, payment status, collection time, and optional notes.

### Contribution
The model classes provide a consistent representation of application data. They can be passed between the service and repository layers and used to map database records into C# objects.

## 3. Booking Repository Updated

**Commit ID:** `4647dcb`  
**Commit Message:** `feat: Booking Repository updated`

### Description
This commit records development work on the repository responsible for booking-related database operations.

### Responsibilities
The booking repository handles database interactions associated with creating, retrieving, and cancelling bookings.

The booking workflow includes working with:
- Customer and booking details.
- The selected court and requested time range.
- The availability of the requested slots.
- Booking amount calculation using the court's hourly rate.
- The relationship between a booking and its reserved slots.
- The payment record associated with a booking.

### Data Consistency
The booking creation logic uses database transactions to coordinate related operations. The intended result is to create the booking, reserve the required slots, and create the corresponding pending payment record as one coordinated operation.

Cancellation logic checks the booking and payment state before updating the booking and releasing its reserved slots.

### Contribution
This repository provides the database operations required by the booking service and helps keep SQL execution separate from application-level business logic.

## 4. Payment Repository Updated

**Commit ID:** `28eaceb`  
**Commit Message:** `Payment Repo updated`

### Description
This commit records development work on the repository responsible for payment-related database operations.

### Responsibilities
The payment repository supports operations for:
- Retrieving a payment using its booking ID.
- Retrieving payment records.
- Collecting cash and updating the payment record.
- Recording the payment method and collection timestamp.
- Storing optional payment notes.
- Checking the booking and payment state before collection.

### Payment Handling
The system uses `Pending` and `Paid` as payment statuses and supports cash as the payment method.

The repository updates the payment status and collection details when a cash payment is successfully recorded.

### Data Consistency
Database transactions are used during cash collection so that the payment update is handled as a coordinated database operation.

### Contribution
This commit develops the data-access functionality required to manage payment records independently of the console interface.

## Development Summary

The commit history shows the project progressing from its initial baseline to model development, repository implementation, court management, console integration, and subsequent feature updates.

The development is organized around a separation of responsibilities:

- **Models** represent the application's data.
- **Repositories** handle database operations.
- **Services** contain business logic and validation.
- **Program.cs** provides the console interface and coordinates the management workflows.

Git is used to track these changes incrementally, making it possible to review the development history and identify the changes introduced at each stage.
